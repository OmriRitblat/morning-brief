Netanyahu's bloc fell short of a majority. Now Israel's president begins talks on who forms the next government

Neither camp has 61 of 120 seats, so the next government depends on deals between parties that have ruled each other out.

In the October 27 election, parties opposed to Benjamin Netanyahu won 67 of the Knesset's 120 seats, and his right-wing and ultra-Orthodox bloc won 53, according to the Times of Israel. Likud is the largest single party with 27 seats, and Gadi Eisenkot's Yashar party has 21. The 67 opposition seats include 48 held by Jewish-led parties and 19 held by the Arab-majority Joint List and Ra'am. A government needs 61 votes, so the opposition has the numbers on paper but not the agreement. Yashar, B'Yachad and Yisrael Beytenu have said they will not sit in a coalition with the Arab, non-Zionist parties. The Joint List's Ahmad Tibi has said his party would back an anti-Netanyahu government from outside, without joining it.

President Isaac Herzog said on Sunday he will receive the official results on Wednesday, November 4, from Central Elections Committee chairman Justice Noam Sohlberg, and then hold consultations in which each faction names the person it recommends as prime minister. He urged party leaders to "stop climbing trees, and face the reality" and signaled he wants a unity government to avoid another election. Likud's Ofir Katz told Army Radio the party opposes rotating the premiership, while Likud's Benny Biton said Netanyahu wants a unity government. The new Knesset is sworn in on November 10. Netanyahu's allies dispute the result and allege fraud, while the elections committee chairman says the election was conducted properly and the results will not change.

NVIDIA's ReplaySSM speeds up a newer kind of language model

A trick that stores a checkpoint plus a short list of recent inputs, instead of rewriting a huge memory every step.

What happened
NVIDIA and Princeton's Dao AI Lab published ReplaySSM, a technique for hybrid language models that mix state-space (SSM) layers with a few attention layers. NVIDIA reports that at batch size 256 on a B300 GPU, end-to-end decoding is 1.20x to 1.47x faster across four models, and with speculative decoding on 120B-class models at batch size 512, throughput is 1.85x to 2.10x that of vLLM's speculative decoding. At batch size 1 there is no speedup. NVIDIA says it is integrated into TensorRT-LLM, vLLM and FlashInfer. These are the authors' own benchmarks.
What it means, in plain words
A normal chatbot remembers the conversation in a KV cache that grows with every word. An SSM layer instead keeps a fixed-size summary, called its state, that gets updated at every step. The catch is that each step reads and rewrites the whole state, which is slow because memory is the bottleneck. ReplaySSM keeps an old copy of the state plus a short list of recent inputs, and only folds the list into the copy every 16 tokens. It also makes undoing wrong guesses in speculative decoding cheap: rejected inputs are simply overwritten.
Why it matters and how it could be used
Serving costs are mostly about how many users one GPU can handle. Faster decoding of hybrid models, such as NVIDIA's Nemotron family, means more users per GPU and lower cost per answer, and it makes speculative decoding (guessing several words ahead and checking them together) work on these models.

Jargon, explained

State-space model (SSM)
A kind of neural network layer that carries a fixed-size summary of everything so far, instead of storing every past word.
Speculative decoding
A small fast guesser proposes several next words, and the big model checks them all at once, keeping the correct ones.
Memory-bound
Limited by how fast data can be read from memory, not by how fast the chip can calculate.

Sources: NVIDIA Technical Blog

Three tweaks make a big mixture-of-experts model 42% faster on a desktop NVIDIA box

Smarter kernels, a smaller output layer and built-in guessing add up on NVIDIA's DGX Spark.

What happened
NVIDIA engineers tested a 124-billion-parameter mixture-of-experts model (5.1 billion active per token) at batch size 1 on DGX Spark. Three changes, a runtime-compiled kernel library called Humming, FP8 quantization of the output layer, and speculative decoding using the model's built-in NEXTN draft layer, raised decode throughput on the GSM8K math benchmark from 37.81 to 53.89 tokens per second (+42.5%), with accuracy essentially unchanged (96.89% to 96.82%). The post says the much larger +185% figure comes from a synthetic, repetitive workload and should not be expected elsewhere.
What it means, in plain words
A mixture-of-experts model is like a hospital with many specialist doctors: for each word, only a few are consulted, so it is cheaper than using the whole model. But a single user still waits on memory reads for each word. The three tweaks cut how much has to be read (smaller numbers for the output layer) and how many separate steps are needed (guess several words, verify together).
Why it matters and how it could be used
It shows where the time goes when one person runs a big model locally: reading weights from memory. A concrete lesson from the post is that combining the tricks needs care: the guessing model must share the exact same quantized output layer, or acceptance falls to 1.00 and the result is slower than baseline.

Jargon, explained

Mixture of experts (MoE)
A model made of many specialist sub-networks where only a few are used for each word.
Quantization
Storing a model's numbers with fewer bits so they take less memory and read faster.
Tokens per second
How many word pieces the model produces each second.

NVIDIA Sentry puts the security guard for AI agents on the network card

The idea: watch agents from a separate chip they cannot tamper with.

What happened
NVIDIA described Sentry, part of its OpenShell reference architecture, which monitors AI agents and enforces rules on what models, tools and data they can reach. NVIDIA says it runs on BlueField-4 DPUs, which are processors on the network card, in a separate hardware trust domain from the host. It combines a per-agent firewall, an inspecting proxy, policy checks written in Open Policy Agent and memory inspection, and NVIDIA says it can quarantine an agent in milliseconds. NVIDIA says Sentry itself is planned for early next year, while some of the underlying DOCA libraries are available now.
What it means, in plain words
Agents are programs that take actions on their own, like browsing, running code and calling tools. If the guard runs on the same computer as the agent, a compromised agent could switch the guard off. Sentry's claim is that the guard sits on a different chip, the network card, so the agent cannot reach it, like a security camera wired to a separate building.
Why it matters and how it could be used
Companies want agents that act without a person approving every step, and the main fear is an agent being tricked into leaking data. A guard that works even when the host is compromised, if it performs as NVIDIA claims, is one way to allow that. Note this is a vendor claim for a product not yet released.

Jargon, explained

DPU
Data processing unit: a small computer on a network card that handles networking and security work so the main CPU does not have to.
Trust domain
A part of a system protected so that what happens in another part cannot change it.
Open Policy Agent
A tool that checks each request against written rules and answers allow or deny.

Sources: NVIDIA Technical Blog

What RDMA is, and how one machine writes into another's memory without its CPU

Monday track: RDMA and NICs

The big idea: RDMA lets a network card move data straight between your program's memory and a remote machine's memory, so neither operating system nor the remote CPU has to touch each message.

First, the basics

Start with the normal path. When a program sends data over an ordinary TCP socket, it calls the operating system. The kernel copies the data from the program's memory into its own buffers, builds packets, and hands them to the network card. On the other side, the card interrupts a CPU, the kernel copies the data into its buffers, and then copies it again into the receiving program's memory. Every message means system calls, copies and CPU time on both machines.

Memory also matters. A program uses virtual addresses, which the operating system maps to physical memory in pages, usually 4096 bytes each. A network card cannot guess these mappings, and the OS can move pages around. So for the card to read or write a program's memory directly, that memory must be set aside and described to the card in advance. This is called memory registration, and it is a later lesson. For today, just remember that the card is given permission to touch specific memory.

How it works, step by step
  1. Both sides first set up a connection and agree on which memory regions the card may access. The remote side shares an address and a key for its region.
  2. The sending program describes the job in a small request: what to do, which local memory, and for a write, which remote address and key.
  3. The program tells its own network card there is new work, without a system call into the kernel for each message.
  4. The sending card reads the data from local memory itself using DMA (direct memory access), builds the packets and sends them.
  5. The receiving card checks the key and address and writes the data straight into the target memory with DMA, with no remote CPU involvement for a one-sided write.
  6. The sending card records that the job is done in a place the program can check, so the program learns the result without being interrupted.
A practical example
Imagine a storage server holding a block of data in memory and a client that wants to read it. With plain TCP, the server's CPU receives the request, finds the data, copies it and sends it. With an RDMA read, the client's card fetches the bytes from the server's memory directly, and the server's CPU is not involved in that transfer at all. The server's CPU stays free for other work.
Why it matters for XLIO
XLIO is built on NVIDIA ConnectX cards, which are RDMA-capable hardware. XLIO does not give you RDMA between machines, since it speaks ordinary TCP and UDP, but it uses the same ideas on the local side: queues shared with the card, registered memory and polling instead of kernel calls. Understanding RDMA is the clearest way to understand what the card can do for you.
Key numbers
Standard page size4096 bytes
ConnectX-7 maximum speed400 Gb/s
Common misconception
A common misconception is that RDMA makes the network itself faster. It does not change the wire speed. It removes the work around the wire: kernel calls, copies and interrupts. That is where most of the delay and CPU cost for small messages comes from.

Jargon, explained

DMA
Direct memory access: a device reads or writes main memory itself, without the CPU copying each piece.
Kernel
The core of the operating system, which controls hardware and runs the networking code.
Memory registration
Telling the network card, and locking down in place, the memory it is allowed to read and write.
One-sided operation
An operation, like an RDMA write, completed by the cards alone without the remote program taking part.
Self-test: Why does the memory have to be registered with the card before RDMA can use it?

Because the card moves data by itself using physical addresses, and the operating system could otherwise move or swap out the pages underneath it. Registration pins the memory in place and gives the card a safe, permitted description of it, plus a key the remote side must present.
