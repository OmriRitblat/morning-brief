Eisenkot wins 67 recommendations for prime minister, but a government is far from certain

Israel's president will decide on Sunday who gets the first chance to build a coalition.

After the October 27 election, President Isaac Herzog met party delegations on Thursday to hear whom each party wants as prime minister. Gadi Eisenkot, leader of the Yashar party, was recommended by 67 of the 120 members of Knesset: Yashar's 48-seat four-party bloc plus 19 seats from the two Arab-led parties, the Joint List and Ra'am. According to the Times of Israel, that is the largest number of recommendations for any candidate since 2015. Benjamin Netanyahu was recommended by 46 members, which Herzog said is his outgoing coalition's 53 seats minus the 7 seats of United Torah Judaism, which declined to recommend him.

A recommendation is not a government. Yashar says it will not sit with Netanyahu and wants to negotiate first with allied opposition parties. Joint List MK Ahmad Tibi said his party would back a minority government from outside but would not give it a safety net. Eisenkot has said coalition partners must call Hamas a terrorist organization, and Ra'am chairman Mansour Abbas stopped short of saying that explicitly. Likud called for a broad national government of Jewish-led Zionist parties and called Eisenkot's bloc the disaster bloc, language Herzog criticized. Herzog said the result was clear but that he would hold more talks before assigning the mandate on Sunday. The new Knesset is sworn in on November 10.

Sources: Times of Israel, Ynet

NVIDIA says its new Vera CPU runs AI agents faster and with less power

NVIDIA is now selling its own processor for the 'helper' work around AI models.

What happened
On November 5 NVIDIA published results for Vera, its own CPU (the general-purpose processor, as opposed to the GPU). NVIDIA says that in a 100-megawatt data center, Vera runs 1.6 times more agents per watt than the fastest x86 chip, and runs agents 2 times faster than the most energy-efficient x86 chip. Partners reported: Perplexity ran agentic coding tasks 1.5 times faster; DeepInfra saw up to 2.2 times the speed on agent orchestration; and Daytona started 1,000 agent sandboxes in 10.8 seconds versus 88.4 seconds on x86.
What it means, in plain words
An AI agent is a program where a model repeatedly decides what to do, then runs tools such as code, searches or databases. The model runs on GPUs, but all the tool work runs on ordinary CPUs. As agents multiply, those CPUs become a bottleneck. NVIDIA is saying its CPU is built for exactly this job.
Why it matters and how it could be used
If agents become the main way people use AI, the CPU side of a data center matters as much as the GPU side. A company running thousands of coding agents could start each agent's isolated workspace almost instantly and pay less for electricity. These are NVIDIA's and its partners' own numbers.

Jargon, explained

CPU vs GPU
A CPU is a flexible processor good at many different jobs one after another; a GPU does huge amounts of simple math at the same time.
Sandbox
A sealed, disposable workspace where an agent can run code without being able to harm anything outside it.
x86
The processor design used by Intel and AMD chips, which currently run most servers.

Sources: NVIDIA blog

NVIDIA: the AI memory wall is solved by a hierarchy, not just more memory

Long conversations and agents need to remember a lot, and GPU memory is running out.

What happened
In a post on November 5, NVIDIA says agent workflows can carry up to 3 million tokens of context across repeated calls, and that GPU memory (HBM) mostly holds the model weights and the KV cache, the model's short-term memory of the conversation. Its answer is a hierarchy: HBM, then CPU memory, then local SSDs, then shared storage. It also uses 4-bit numbers (NVFP4) to shrink weights and KV cache, spreads weights over up to 72 GPUs in an NVL72 rack, and uses its Dynamo software to park idle context in cheaper storage and bring it back before it is needed. NVIDIA claims, on a SemiAnalysis benchmark, up to 30 times more throughput per dollar for Vera Rubin NVL72 than GB300 NVL72, while HBM per GPU grew only about 3%.
What it means, in plain words
Think of a chef's counter, a fridge and a warehouse. Only what is being cooked right now needs to be on the counter. NVIDIA wants to keep each conversation's memory on the right level and move it between levels at the right time, so expensive GPU memory is not wasted on conversations that are paused while a tool runs.
Why it matters and how it could be used
Memory is getting scarce and expensive, and it limits how many users one machine can serve. Smarter placement means the same hardware can serve more people. The 30 times figure is NVIDIA's own claim and covers the whole system, not memory alone.

Jargon, explained

KV cache
The notes a model keeps about everything said so far so it doesn't have to re-read the whole conversation for each new word.
HBM
High-bandwidth memory: very fast memory stacked right next to the GPU chip.
Token
A small piece of text, roughly three quarters of a word, that models read and write.
NVFP4
NVIDIA's 4-bit number format, which stores each value in less space than the common 8-bit one.

Sources: NVIDIA blog

Why not to wait even a few minutes before fleeing a tsunami

A computer simulation suggests that a short delay can decide whether people reach safety.

This Nature news item is behind a login, so this summary is based only on the description Nature publishes in its feed. It reports on a simulation of people evacuating from a tsunami. The main finding, in Nature's words, is that even brief hesitation can determine whether people reach safety.

The reason is simple arithmetic: a tsunami arrives at a fixed time, and the distance people must cover to reach high ground does not change, so every minute spent waiting is a minute taken from the time available to walk or run. I could not read the article, so details such as which coast was modeled, how many people were simulated and how large the effect is are not included here.

  1. What they found: a few minutes of delay can be the difference between reaching safety and not.
  2. How they found it: a computer simulation of an evacuation (further details not available in the feed).
  3. Why it matters: it supports evacuating immediately after a warning or strong shaking rather than waiting to confirm.

A computer model that plays out a situation many times to see what happens under different choices.

The KV cache: what it stores and why it grows with every token

Friday track: AI inference

The big idea: While a model writes its answer one token at a time, it keeps a notebook of what it already worked out about every earlier token, so it never has to redo that work. That notebook is the KV cache, and it gets longer with every token.

First, the basics

A language model reads text as tokens, small pieces of words. To produce each new token it uses attention: the new token looks back at all earlier tokens and decides which are relevant. Think of writing a sentence while glancing back over everything you've written.

Inside attention, every token is turned into three lists of numbers: a query (what am I looking for?), a key (what do I contain, as a label?) and a value (what information do I hand over?). A new token's query is compared with every earlier token's key to get scores, and those scores decide how much of each earlier value gets mixed in.

How it works, step by step
  1. Prefill: the model reads your whole prompt at once and, for each token in every layer, computes its key and value.
  2. It stores those keys and values in GPU memory. That stored collection is the KV cache.
  3. Decode begins: the model produces the first new token. Its query is compared against all the cached keys.
  4. For that new token the model computes just one new key and one new value per layer and appends them to the cache.
  5. Next token: repeat, reusing every earlier key and value from the cache instead of recomputing them.
  6. The cache gets one entry larger per layer with every token, for the prompt plus the answer, until the answer ends.
A practical example
Imagine a coding agent that has pasted a 50,000-token codebase into the prompt. Without a KV cache, every new word of the answer would force the GPU to redo the keys and values for all 50,000 tokens. With one, it computes them once during prefill and then only adds one new entry per step. The price is memory: those 50,000 tokens sit in GPU memory the whole time, for every user being served at once.
Why it matters for XLIO
When a service is split across machines, the KV cache sometimes has to move over the network, and NVIDIA's Dynamo and NIXL do this over fast RDMA networking. That is the connection to your world of NICs and zero-copy transfers.
Key numbers
KV cache size per token2 (keys and values) x layers x KV heads x head dimension x bytes per number
Example: a model with 32 layers, 8 KV heads, head size 128, 16-bit numbers131,072 bytes, about 128 KiB per token
Same example at 8,000 tokens of contextabout 1 GiB for one user
Common misconception
People often think the cache stores the text or the model's answers. It doesn't: it stores the intermediate keys and values for each token in each layer, which are numbers, not words. That is why it can be much bigger than the text itself.

Jargon, explained

Token
A small piece of text, roughly three quarters of a word.
Attention
The step where a token looks back at earlier tokens and decides which matter.
Prefill
The first phase, where the model reads the whole prompt at once.
Decode
The second phase, where the model writes the answer one token at a time.
HBM
High-bandwidth memory: the fast memory on the GPU where the cache lives.
Self-test: Why does the KV cache make each new token cheaper to compute, but make the server run out of memory sooner?

It saves the keys and values of earlier tokens, so each step only computes one new entry instead of redoing everything, which saves computation. But those saved entries stay in GPU memory and grow with every token and every user, so memory fills up.
