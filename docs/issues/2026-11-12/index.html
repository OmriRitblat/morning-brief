Google's Gemini Decisions API answers yes-or-no and multiple-choice questions in a fraction of a second

Instead of writing out an answer word by word, a new model scores the possible answers in one go and says how confident it is.

What happened
On November 11, Google launched the Gemini Decisions API, running a new model called Gemini Decision 1. You send one input, which can be text, images, audio, video or PDFs up to 256,000 tokens, plus up to 1,000 questions about it. Each question is yes or no, multiple choice with up to 255 options, or a score on a scale. The model answers all of them in a single pass and returns a probability and a confidence score from 0 to 1 for each. Google says latency is 150 to 250 milliseconds end to end and stays almost flat from 1 to 100 questions. Pricing is 10 cents per million input tokens, with nothing charged for output, and Google says that is nearly five times cheaper than its Gemini 3.5 Flash-Lite model on its test suite.
What it means, in plain words
A normal chatbot answers by writing text one token at a time, and each token costs another trip through the model. But many decisions inside software are really multiple-choice questions: which tool should the agent use, does this message break the rules, is this photo a spill or not. Here the model reads the input once and scores each allowed answer directly, like a student who reads the exam passage once and then ticks boxes, instead of writing an essay for each question. The confidence number tells your program when the model is unsure, so it can send that case to a bigger model or a person.
Why it matters and how it could be used
Agents make dozens of small decisions per task, and each one usually costs a full model call. Turning them into one cheap, fast, scored call cuts both waiting time and cost. Google says its Gemini Notebook app uses it to route each question to the right model and saw up to 40 percent lower latency. A developer could use it to check every incoming support ticket against 20 policy rules in one request.

Jargon, explained

Token
A chunk of text, roughly three quarters of a word, that a language model reads and writes.
Forward pass
One trip of the input through the model's layers to produce an output.
Routing
Choosing which model, tool or handler should deal with a request.
Calibrated
When the model says 80 percent sure, it is right about 80 percent of the time.

Sources: Google blog

DeepMind's AlphaGenome 2 predicts what a DNA change does in one specific kind of cell

The same spelling mistake in DNA can matter in an immune cell and do nothing in a skin cell; the new model is built to tell the difference.

What happened
On November 11, Google DeepMind released AlphaGenome 2, a model that reads a stretch of DNA one million letters long and predicts how it controls genes, such as how strongly a gene is switched on, in a cell type you choose. The first AlphaGenome predicted many tissues at once; version 2 is conditional: you tell it the cell type or state, and it predicts for that one. It was trained on more than 100 million single-cell profiles across 68 tissues, DeepMind says. On an immune-cell test set covering 28 cell types, DeepMind reports it found 30 percent of likely causal variants, versus 16 percent for comparison models. It is available free for non-commercial research through an API, with commercial access in private preview. DeepMind says it is for research only, not for diagnosis.
What it means, in plain words
Every cell in your body carries the same DNA, like every branch of a chain restaurant having the same recipe book. What differs is which recipes each branch actually cooks. Most disease-linked DNA changes are not in the recipes themselves but in the notes that say when to cook them. AlphaGenome 2 tries to predict, for a particular kind of cell, whether a given change to those notes turns a gene up, down or not at all. You can even describe a new cell state from a few dozen measured cells, and it adapts without retraining.
Why it matters and how it could be used
Large genetic studies find thousands of DNA spots linked to diseases but usually can't say which one is the real cause or in which cells it acts. A model that narrows this down tells biologists which experiment to run first. For example, DeepMind shows it pinpointing a variant linked to inflammatory bowel disease that overactivates a gene only in gut immune cells, matching an earlier lab finding.

Jargon, explained

Variant
A spot where one person's DNA spelling differs from another's.
Gene expression
How actively a gene is being used to make its product in a cell.
Single-cell data
Measurements taken from individual cells instead of a ground-up tissue sample.

Huawei releases MACaQ, a tool that shrinks AI models to run on smaller hardware

An open-source quantizer that makes models smaller and faster while trying to keep their answers almost unchanged.

What happened
Huawei's research lab published MACaQ, an open-source tool under the Apache 2.0 license, with an accompanying paper. It converts models to 2, 3 or 4 bit formats for popular local and server engines such as llama.cpp and vLLM, and works on text, image, video and audio models. Huawei reports it can quantize a 122-billion-parameter model in 64 minutes using 32.5 gigabytes of GPU memory. On a 27-billion-parameter Qwen model running in vLLM, it reports 2.33 times faster prompt processing and 2.58 times faster text generation than the 16-bit original, with only a small rise in error.
What it means, in plain words
A model is basically billions of numbers. Normally each is stored with 16 bits. Quantization stores each one with only 4 bits, or even fewer, like rounding prices to the nearest shekel instead of keeping the agorot. The model gets about four times smaller and faster to move through memory, but rounding adds small errors. The trick is choosing the rounding carefully, using a little sample data to see which numbers matter most, so the answers barely change.
Why it matters and how it could be used
When a model generates text, the speed limit is usually how fast its numbers can be pulled from memory, not how fast the chip can do math. Smaller numbers mean less to move, so more speed and lower cost per answer. That is why quantization is one of the main ways companies cut inference bills, and why a large model can fit on a single laptop or a single GPU instead of several.

Jargon, explained

Quantization
Storing a model's numbers with fewer bits so it takes less memory and runs faster, at some cost in accuracy.
Inference
Using a trained model to produce answers, as opposed to training it.
Perplexity
A measure of how surprised a model is by real text; lower is better.

The first-ever picture of a black hole passes an independent check

A separate team, using a different method that avoids the usual calibration guesswork, got the same glowing ring.

In 2019 the Event Horizon Telescope, a network of radio telescopes spread across the planet that works like one Earth-sized dish, released the first image of a black hole: a bright orange ring around a dark center in the galaxy M87. Making that picture required many judgment calls about how to correct and combine the data, so some scientists wondered whether the ring was partly a product of those choices.

Now a four-person team at CSIRO, Australia's national science agency, led by Samuel Lai, has reprocessed the original data with its own method, reported in Nature on November 11. Instead of combining measurements from pairs of telescopes, it combines them in groups of three, which cancels out many errors caused by the atmosphere and by each telescope's own quirks. A machine-learning model then rebuilt the image. The result was almost identical in size and shape to the 2019 picture, and the ring appears across several years of data. Lai says the model had no idea what a black hole looked like beforehand, and EHT director Laurent Loinard called it an elegant, entirely independent method.

  1. What they found: an independent reanalysis recovers the same ring around M87's black hole, so the ring looks like a real feature, not an artifact of how the image was made.
  2. How: they combined data from telescopes in groups of three, which cancels each telescope's individual errors, and used machine learning that was not taught what to expect.
  3. Why it matters: in science a striking result is only trusted after someone else reproduces it another way; this is the first fully independent confirmation of the famous image.

Jargon, explained

Black hole
A region where gravity is so strong that not even light escapes; we see the hot gas glowing around it, with a dark shadow in the middle.
Radio telescope network
Telescopes far apart that record the same signal at the same time; combining their recordings gives the sharpness of one telescope as wide as the distance between them.
Calibration
Correcting each instrument's own errors and delays before combining the data.

How training works at a glance: forward pass, backward pass, gradients

Thursday track: AI compute and interconnect

The big idea: Training is a loop repeated millions of times: the model makes a guess, a single number measures how wrong it was, the backward pass works out which way to nudge every weight to be a little less wrong, and the optimizer nudges them. Nothing is learned during the guess; all the learning happens in the nudge.

First, the basics

A neural network is a stack of layers, and each layer is mostly a matrix multiplication: it multiplies its input by a big table of numbers called weights and passes the result to the next layer. A 7-billion-parameter model simply has 7 billion such weights. At the start they are random, so the model outputs nonsense. Training is the process of finding weights that make the outputs good.

To improve something you need a way to score it. The loss is one number that says how wrong the model was on some examples. For a language model the task is predicting the next token, and the loss is cross-entropy: minus the logarithm of the probability the model gave to the correct token. If it gave the right word a probability of 1, the loss is 0; if it gave it 0.2, the loss is about 1.6; the less likely it thought the truth was, the bigger the loss.

A gradient is the slope of the loss with respect to each weight: if I nudge this one weight up a tiny bit, does the loss go up or down, and by how much? Imagine standing on a foggy hillside wanting to reach the valley. You can't see the bottom, but you can feel which way the ground slopes under your feet. The gradient is that slope, measured for billions of weights at once, and you step the opposite way, downhill.

How it works, step by step
  1. Load a batch: a group of training examples, for a language model many sequences of tokens, is copied into GPU memory. Using a batch instead of one example gives a less noisy estimate of the right direction and keeps the GPU busy.
  2. Forward pass: the batch flows through the layers from first to last. Each layer multiplies by its weights and applies a simple function, producing activations. These activations are kept in memory, because the backward pass will need them.
  3. Compute the loss: the final outputs, probabilities for the next token, are compared with the real next tokens, and the cross-entropy is averaged over the batch into one number.
  4. Backward pass (backpropagation): starting from the loss and moving from the last layer back to the first, each layer receives the gradient of the loss with respect to its output. Using the chain rule from calculus and its saved activations, it computes two things: the gradient for its own weights, to update them, and the gradient for its input, which it hands back to the layer before. Frameworks like PyTorch do this automatically, which is called autograd.
  5. Combine gradients: when training on many GPUs, each one processed different examples, so their gradients are averaged across all GPUs before anyone updates. That exchange is all-reduce, next week's topic, and it is pure network traffic.
  6. Optimizer step: every weight is nudged against its gradient. The simplest rule is new weight = old weight minus learning rate times gradient, where the learning rate is a small number that sets the step size. Most large models use Adam, which also keeps two running averages per weight, a momentum and a typical gradient size, to choose a sensible step for each weight.
  7. Clear the gradients and repeat with the next batch. One loop is a training step; a full run is often hundreds of thousands of steps.
A practical example
Take the sentence 'The cat sat on the' with the correct next word 'mat'. In the forward pass, the model gives 'mat' a probability of 0.2, so the loss is minus the log of 0.2, about 1.61. The backward pass finds, for each weight, whether raising it would increase or decrease the chance of 'mat'. After the optimizer step, suppose the model now gives 'mat' 0.25; the loss drops to about 1.39. Now scale it up: training a 7-billion-parameter model on 1 trillion tokens takes about 6 x 7 billion x 1 trillion, roughly 4.2 x 10^22 math operations. On GPUs that each actually deliver about 400 trillion operations per second, that is about 29,000 GPU-hours, which is why training is spread across thousands of GPUs at once.
Why it matters for XLIO
Every training step ends with GPUs exchanging their gradients, and while that happens the GPUs can sit idle, so network latency and bandwidth directly set how fast an expensive cluster trains. NVIDIA moves this traffic with NCCL over RDMA, InfiniBand or RoCE, rather than over regular sockets, for exactly the reasons XLIO exists: skipping the kernel, avoiding copies and polling for completions. Around the training itself, loading data, saving checkpoints and control traffic often run over ordinary TCP, where user-space acceleration such as XLIO can help.
Key numbers
Training compute per tokenabout 6 x number of parameters operations: about 2 forward, about 4 backward (Kaplan et al., 2020)
Backward pass costabout twice the forward pass
Memory for weights, gradients and Adam state with mixed precisionabout 16 bytes per parameter (ZeRO paper), so about 112 GB for a 7B model, before activations
Cross-entropy loss when the right token gets probability 0.2about 1.61
Common misconception
It's tempting to think the gradient tells the model what the right weights are. It doesn't. It only says which direction is downhill right here, and how steep, measured on one batch. Take a huge step and you can jump right over the valley and make things worse. That's why the learning rate is small and the loop repeats hundreds of thousands of times.

Jargon, explained

Weights (parameters)
The adjustable numbers inside a model that training changes.
Activations
The intermediate results each layer produces during the forward pass.
Loss
A single number measuring how wrong the model's predictions were.
Gradient
For each weight, which direction and how strongly changing it would change the loss.
Backpropagation
Computing all gradients by working backwards through the layers using the chain rule.
Learning rate
A small number that sets how big each weight update is.
Optimizer
The rule that turns gradients into weight updates, for example SGD or Adam.
Self-test: Why does the backward pass cost about twice as much computation as the forward pass?

In the forward pass each layer does one big matrix multiplication: input times weights. In the backward pass it needs two of the same size: one to get the gradient for its weights, so they can be updated, and one to get the gradient for its input, so it can pass the signal to the layer before. Two multiplications instead of one gives about twice the work, which is where '2 forward plus 4 backward equals 6 per parameter per token' comes from.
